# WP-TP-DB

연구실 GPU 서버 자원 예약 및 실시간 모니터링 시스템의 데이터 모델·스키마·초기 데이터와 데이터베이스 운영 문서를 관리할 저장소입니다.

[프로젝트 전체 소개](https://github.com/2026-2-web-programming-term-project/.github#readme)

## 관리할 데이터

| 영역 | 주요 데이터 |
| --- | --- |
| 연구실·회원 | 소속 연구실, 회원, 역할·이용 상태, 초대 코드·인증 |
| 자원 | 서버·GPU 노드 식별자와 사양, 점검 정보, 상태 수신 시각 |
| 예약 | 자원·예약자·목적·기간·상태, 취소와 조기 종료 이력 |
| 정책 | 예약 단위·최대 연속 시간·알림 기준과 변경 이력 |
| 알림·통계 | 대기 신청, 알림·읽음 상태, 예약 시간 집계에 필요한 데이터 |

## 데이터 설계 원칙

- 연구실 소속과 참조 관계를 보존하고 예약·운영 이력을 유지합니다.
- 예약의 시작·종료 시각과 실제 GPU 모니터링 데이터를 구분합니다.
- 여러 API 인스턴스가 동시에 요청해도 겹치는 예약이 확정되지 않도록 트랜잭션·잠금 방식을 설계하고 검증합니다.
- 통계는 기간 경계의 예약 시간, 조기 종료와 취소·점검 처리 기준을 명시합니다.
- 스키마 변경과 초기화 절차를 버전 관리하고 백업·복구 검증을 문서화합니다.

## 현재 상태와 기술 선택

2026-11-02 기준 README와 Apache-2.0 라이선스가 있습니다. ERD·스키마·마이그레이션·초기 데이터·실행 스크립트는 작성 예정입니다.

제안서는 MySQL을 예상 기술로 제시하며, API 초기 빌드에는 MariaDB JDBC 드라이버가 선언되어 있습니다. 최종 엔진·버전·관리형 서비스 사용 여부는 확정 예정입니다. Cassandra·Redis 등 추가 저장소는 실시간 기능과 상태 관리 요구를 확인한 후 선택합니다.

## HA 설계 계획

애플리케이션 ASG와 별도로 데이터 계층의 장애 복구를 설계합니다. RDS Multi-AZ 등의 대안을 검토하고, 연결 재수립·예약 정합성·백업 복원·DB 연결 한도를 함께 확인할 계획입니다. HA 구성과 읽기 처리량 확장은 별도 요구사항으로 다룹니다.
